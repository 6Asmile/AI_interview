# 词汇表与实现状态口径

## 五种实现状态

### `implemented`：当前已实现

至少有当前代码入口与可验证的持久化、响应或运行结果，且本轮没有发现会阻断所述主路径的问题。它不自动等于“生产就绪”。例如 `CareerDashboardView` 在独立 PostgreSQL 与当前候选人页面上返回合成事实、岗位、简历和任务聚合，可以说该读取链路已实现；没有容量压测则不能说它已验证十万并发。

### `partial`：部分实现

主要模型或服务存在，但 UI/API/异步/恢复中的一段缺失或本轮已观察到阻断。例如 Broker DLQ 的目标契约与管理页面边界已经定义，但真实 RabbitMQ 读取、dry-run、原路由校验和失败不 ACK 的重放链尚未接通，所以只能标成部分实现。

### `legacy-compatible`：遗留兼容

代码仍为旧页面、旧接口或历史数据服务，新的权威链路已在别处建立。`interactions` 的旧点赞/收藏/关注模型与 `community` 原生互动并存，就应说明它是兼容层和收敛风险，而不是两个同等推荐的新实现。

### `target-design`：目标设计

在架构、配置或 ADR 中定义了方向，但当前没有足够实现/运行证据。多可用区 PostgreSQL、跨区对象存储灾备、自动扩缩容与完整 SLO 闭环属于目标设计，不能写进“已经完成”。

### `pending-verification`：待验证

代码线索存在，但当前环境没有完成必要验证，或验证被外部条件阻断。例如需要真实第三方 OAuth 回调、收费模型、生产密钥或专用媒体设备的功能，在未验证前保持该状态。

## 证据优先级

1. 本轮可重复的运行结果、测试与数据库查询。
2. 当前 Commit 的模型、迁移、路由、服务、配置和约束。
3. 当前前端页面和 Network/Server 日志。
4. 测试代码所表达的契约。
5. 历史文档、提交信息和迁移说明，仅用于解释时间线。

当证据冲突时，优先记录冲突而不是挑选最乐观的一项。截图显示空态、数据库有记录、服务器日志又显示 404，这三项合起来说明“数据存在，当前客户端没有正确取到”，不是“数据不存在”。

## 核心术语

| 术语 | 在 iFaceoff 中的准确含义 |
|---|---|
| Career Fact | 带类型、来源、确认状态和内容的职业事实，是职业画像与简历证据的输入，不是任意聊天记忆 |
| Job Target | 候选人当前准备的目标岗位及 JD snapshot/技能要求关联 |
| Resume | 简历身份与当前指针；不是每次保存的全部内容 |
| ResumeVersion | 已确认内容的不可变版本源，版本号在单份 Resume 内唯一 |
| ResumeDraft | 可编辑工作副本，可基于某个 ResumeVersion；不是公开分享版本 |
| DesignRevision | 模板、主题和布局选择的版本，与内容版本分离 |
| Artifact | PDF/HTML 等渲染制品及生成状态、哈希、存储位置 |
| InterviewSession | 一次业务面试会话及岗位/JD/模式 snapshot |
| Agent Run/Execution | Agent 的一次可恢复执行，和业务会话状态不是同一个概念 |
| Checkpoint | LangGraph 图运行状态的持久化断点，目标上使用独立 PostgreSQL |
| SSE cursor | 客户端已收到的事件序号，用于断线后从缺口继续读取 |
| RAG | 检索增强生成；在本项目中包含版本、切块、索引、过滤、融合、重排、扩展和 trace |
| Qdrant | 向量候选召回；不是知识内容的唯一权威库 |
| Meilisearch | 关键词/BM25 类候选召回与过滤；不保存业务权威版本 |
| RRF | Reciprocal Rank Fusion，用排名而非不可比的原始分数融合多路候选 |
| Model Gateway | Provider/Deployment/Alias/Policy/Budget/Ledger/Attempt 的治理层 |
| Operation | 平台异步执行的 PostgreSQL 权威状态；包含输入/结果引用、attempt、lease、fencing、事件序号、取消和终态，不等同于 Celery task id |
| OperationEvent | 与 Operation 状态同事务提交、只追加的阶段级耐久事件；逐 Token 实时流不写入该表 |
| OperationDispatchOutbox | 与领域输入和 Operation 同事务创建的高成本命令派发意图；Broker 消息只携带 operation id |
| IntegrationOutbox | 与业务事实同事务创建的领域事件发布意图；使用版本化 Envelope 和有限摘要 |
| ConsumerInbox | 消费者的去重、claim、lease、fencing 与处理状态；不等于消息永不重复 |
| Claim | Worker 在数据库中以条件更新取得一次执行权，返回后续提交必须携带的身份与栅栏 |
| Lease | 有 owner 和到期时间、可 heartbeat/renew 的暂时执行租约；租约本身不保证最终正确性 |
| Fencing token | 每次新 claim、取消或 stale recovery 提高的单调令牌；旧 Worker 用旧令牌无法晚提交 |
| Publisher Confirm | Broker 对发布接收结果的确认；不能证明数据库已经标记 published，也不消除重复 |
| Mandatory Routing | 发布消息无法路由时让 Publisher 得到失败，而不是静默丢弃 |
| Idempotency key | 在用户、scope、key 等边界内唯一的请求标识，重试时复用结果或拒绝重复副作用 |
| DLX/DLQ | RabbitMQ 死信交换机/队列；队列参数是声明的一部分，不能用同名不同参数热覆盖 |
| Database Dead | PostgreSQL Outbox/Dispatch 超过发布上限后的可审计状态；不是 RabbitMQ Broker DLQ |
| Capability readiness | 按普通读取、安全流程、高成本写、异步受理和实时能力分别报告 ready/degraded/blocked |
| Staff | 独立运营/治理身份，不是候选人 `User.is_staff` 的简单页面包装 |
| Break Glass | 受审计、需理由、限时的高风险访问流程，不是永久超级权限 |
| current | 截图来自当前代码与当前运行环境 |
| current-partial | 当前界面真实存在，但显示已核验的空态、错误或未完成集成 |
| historical | 只用于演进说明，不能当作当前可用证据 |

## 面试口径检查

回答完任何项目问题后，用四个问题自查：

1. 我说的是当前实现、部分实现还是目标设计？
2. 我能指出至少一个文件/类/模型/测试吗？
3. 正常路径之外，我说明了事务边界、失败和恢复吗？
4. 如果截图与代码不一致，我是否解释了集成差距？

只要第四问答不上来，就回到 [[09-代码-API-数据事实索引]] 和 [[13-截图证据清单]] 查证，不要现场补造。
